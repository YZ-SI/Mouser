# #205 [Bug] Horizontal Scroll shortcuts repeats on touchpad.

> *This was generated by AI during triage.*

**State:** ready-for-agent

## Root cause (Mouser evidence)

- `core/mouse_hook_windows.py:456` (`elif wParam == WM_MOUSEHWHEEL`): every horizontal wheel message seen by the global `WH_MOUSE_LL` hook is turned into `hscroll_left/right` and, if bound, blocked (`should_block`). The hook struct carries no source-device identity.
- `core/mouse_hook_windows.py:339` only skips events flagged injected. Precision-touchpad two-finger pan arrives as ordinary `WM_MOUSEHWHEEL`, so it is not skipped.
- `core/mouse_hook_base.py:353` (`_should_intercept_events`) only checks that *some* Logitech is bound (`_connected_device is not None`). It does not check which device produced the event. Its docstring describes the same trackpad failure for KVM, but the guard is host-wide, not per-event.
- Raw Input already identifies the source: `_process_raw_input` (`core/mouse_hook_windows.py:543`) drops everything where `_is_logitech(hDevice)` is false (`:559`). That information is never correlated with the LL-hook wheel event.

Confidence: likely. The issue has no logs, but the code path is unambiguous: a bound Logitech mouse plus a touchpad wheel message gives remap and swallow. Not verified: whether a precision touchpad also emits a Raw Input mouse record (it normally does not, which is what makes the Raw Input attribution work).

## Agent Brief

**Category:** bug
**Summary:** Horizontal and vertical wheel remaps must fire only for wheel input that originates from the bound Logitech mouse, never from a touchpad or other pointer.

**Current behavior:**
While a Logitech mouse is connected, a laptop precision touchpad two-finger horizontal pan is treated as a Logitech horizontal wheel tilt. It triggers the user's `hscroll_left`/`hscroll_right` bindings and the native scroll is swallowed, so the touchpad cannot pan.

**Desired behavior:**
The agent's mouse hook decides per event whether it came from a Logitech device. Wheel events (vertical and horizontal) without a Logitech origin pass through untouched: no remap, no swallow, no scroll inversion. Logitech wheel events behave exactly as before. When the agent cannot attribute an event, it fails open (passes it through).

**Key interfaces:**
- Hook event classifier: given a wheel message from the low-level hook, returns Logitech or other. Use Raw Input (`WM_INPUT`, `RIM_TYPEMOUSE`, device handle whose interface name contains VID `046d`) as the attribution source, for example a single-slot "recent Logitech wheel" record (timestamp plus sign) matched against the LL event within a short window.
- The classifier is a pure function over (record, event, now), unit-testable without Win32.
- No unbounded queues: the record is one slot or a small fixed ring.

**Acceptance criteria:**
- [ ] Unit test: a wheel event with no matching Logitech Raw Input record inside the window is classified "other" and the handler passes it through (not blocked, not remapped).
- [ ] Unit test: a wheel event with a matching Logitech record is classified "Logitech" and the existing bound-action path runs.
- [ ] Unit test: an expired or sign-mismatched record is not matched.
- [ ] Manual (MX Master 2S over Unifying plus a laptop touchpad): with `hscroll_left`/`hscroll_right` bound to custom shortcuts, a touchpad two-finger horizontal pan pans normally and fires no shortcut; tilting the mouse wheel fires the shortcut.
- [ ] Manual: same with `invert_hscroll` enabled; the touchpad is not inverted or re-injected.
- [ ] No per-event heap allocation in the hook path.

**Out of scope:**
- A UI to choose which pointing device to remap.
- Touchpad gesture remapping.
- Linux/macOS behavior.
