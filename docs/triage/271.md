## Root cause (Mouser evidence)

Confidence: **guess** (mechanism located; which condition fails on this mouse is unknown; no device JSON or log).

- Swipe direction rows are shown only if the capability inventory reports `gesture_directions`. That is computed in `core/logi_devices.py:744-748` as: gesture control divertable AND `gesture_rawxy_enabled is not False` AND `_control_has_raw_xy(control)`. `supported_buttons` then strips `gesture_left/right/up/down` when false (`core/logi_devices.py:306-317`, applied via `core/logi_devices.py:795-813` and `core/logi_devices.py:908`). The UI consumes the filtered list at `ui/backend.py:2478-2483`.
- `_control_has_raw_xy` needs raw-XY bits in the REPROG_V4 key flags (0x0100/0x0200) or mapping flags (0x0010/0x0040) (`core/logi_devices.py:87-90,705-716`).
- `gesture_rawxy_enabled` is false when divert-with-RawXY was rejected and the code fell back to button-only (`core/hid_gesture.py:1695-1727`).
- Either condition could fail on an MX Master 2S (catalog `core/logi_device_catalog.py:228-239`, layout `core/logi_device_catalog.py:880-945`, PID 0xB019). This would explain why older versions (static button list) showed directions while v3.7.3 (capability-derived) hides them. Hypothesis only.
