# #294 [Bug] Actions Ring text is flipped/rotated and labels cannot be customized

> *This was generated by AI during triage.*

**State:** ready-for-agent (per-slot custom label is an enhancement; "rotated text" is not reproducible from source and is covered as an invariant)

## Root cause (Mouser evidence)

Confidence: **confirmed** for labels; rotation **not located**.

- Ring slot text is derived, never user-defined: `_resolve_ring_label` (`ui/actions_ring_overlay.py:69-78`) uses a fixed map (`RING_LABEL_MAP`, line 18) or, for `custom:` actions, the generated combo string via `custom_action_label` (`core/key_simulator.py:18-34`); the ring is fed from `ui/backend.py:2219-2220`. Config stores only the action id per slot (`actions_ring_slots`, see the config dump in #278), so there is nowhere to store a display name. The reporter saw raw `custom:ctrl+a` text; a comment says the readable-combo fallback is #317 and an optional name field is PR #326 (not verified by me).
- Rotation: the overlay paints labels with `painter.drawText` on an unrotated rect centered at the sector position (`ui/actions_ring_overlay.py:361-386`). There is no `rotate()` call in that file, so text should already be upright. The cause of the reported flipped text is not located (could be a screenshot artifact, DPI scaling or a different build). Needs a repro on MX Master 4 if it persists.

## Agent Brief

**Category:** enhancement
**Summary:** Actions Ring renders every slot label upright, and each slot may carry an optional display-only name that does not change the assigned action.

**Current behavior:**
Labels are generated from the action id; custom shortcuts show the key combination. Users cannot set their own text per slot.

**Desired behavior:**
Each ring slot (global ring and per-profile ring) has an optional `label` string. When non-empty it is displayed; when empty the existing derived label is used (readable key combo for custom shortcuts, e.g. `Ctrl + Alt + A`, never the raw `custom:` id). The label never affects the action or shortcut that runs. All labels are drawn horizontally, upright, wrapped inside the sector, at every slot position, clipped to a maximum length (e.g. 24 chars) with ellipsis.

**Key interfaces:**
- `config.json`: additive optional per-slot names, e.g. `actions_ring_labels: [string]` parallel to `actions_ring_slots` (absent or empty entries mean "derive"). Older configs load unchanged; Mouser ignoring the key keeps working.
- Ring renderer input: `RingSlot { action_id, label }`, text drawn without a rotation transform.
- Ring editor in the GUI: a label text field per slot.

**Acceptance criteria:**
- [ ] Unit test: label resolver returns the custom label if set, else `Ctrl + Alt + A` for `custom:ctrl+alt+a`, never a string starting with `custom:`.
- [ ] Unit test: a config with and without the new key round-trips without loss; the action id list is untouched when a label changes.
- [ ] Render/layout test: for 4 to 8 slots, each label's text transform is identity rotation (upright) at every position.
- [ ] Manual (MX Master 4 or any device that opens the ring): set slot label "ChatGPT" for Ctrl+Alt+A; the ring shows "ChatGPT"; releasing on it sends Ctrl+Alt+A.

**Out of scope:**
- Icons for slots.
- Per-device ring layouts.
- Haptic ring behavior.
