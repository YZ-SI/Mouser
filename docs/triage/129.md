## Agent Brief

**Category:** bug
**Summary:** The agent's low-level mouse hook must keep working and must be self-healing, and custom navigation-key shortcuts must be sent with correct extended-key semantics. (Narrowed to what the rewrite can specify without the reporter's answers.)

**Current behavior:**
Custom shortcuts such as `custom:ctrl+pageup` are saved but side buttons and horizontal tilt on some systems never produce events; there is no detection that the hook has stopped receiving events or was removed by Windows.

**Desired behavior:**
- Key synthesis for `pageup`, `pagedown`, `home`, `end`, `insert`, `delete`, arrows uses `KEYEVENTF_EXTENDEDKEY`, so they work with NumLock either way. F1-F24 and `ctrl+pageup` records and replays correctly.
- The agent logs a one-line event when the hook is installed, reinstalled, or found uninstalled, and exposes hook state to the GUI over the pipe (`hook_installed: bool`, `last_event_age_ms`).
- The hook callback does O(1) work with no allocation, so it stays well below the Windows low-level hook timeout; heavy work happens on another thread via a bounded channel.

**Key interfaces:**
- `parse_shortcut(&str) -> Result<Vec<Key>, ShortcutError>` and `send_combo(&[Key])`.
- IPC status message including hook state.

**Acceptance criteria:**
- [ ] Unit test: `parse_shortcut("ctrl+pageup")`, `"f8"`, `"ctrl+pgdn"`, `"home"`, `"insert"` parse to the expected virtual-key codes; unknown names return `ShortcutError`.
- [ ] Unit test: the `INPUT` array built for `ctrl+pageup` sets the extended flag on `pageup` and not on `ctrl`, with key-ups in reverse order.
- [ ] Manual (MX Master 2S over Unifying): back/forward bound to `ctrl+pageup`/`ctrl+pagedown` switch tabs in a browser.
- [ ] Hook state visible in the GUI diagnostics.

**Out of scope:**
- Diagnosing the reporter's Bluetooth side-button issue until answers arrive.
- Tray empty-window bug (Qt-specific).
