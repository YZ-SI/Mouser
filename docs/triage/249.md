# #249 [Bug] Pointer Speed (DPI) not being set after Mouse resumes from Sleep

> *This was generated by AI during triage.*

**State:** `ready-for-agent`

## Root cause (Mouser evidence)

- `core/engine.py:1335-1338`: replay of saved settings only fires when `hid_features_ready` changes.
- `core/hid_gesture.py:3361-3380`: a sleeping mouse is tracked by `_device_asleep`; on wake ("Device woke from sleep") only `_on_connect` is called, no settings replay. If the HID handle stays valid across the mouse power cycle, `hid_features_ready` may never flip, so nothing is re-sent.
- The mouse reverts to its onboard default DPI after power off/on while Mouser believes it is configured (no log lines, as the reporter says).
- Reporter says 3.6.0 was fine and 3.7.0 regressed; the maintainer comment attributes it to the link-up case not replaying (PR #264 covers sleep/resume only). I did not diff versions.

Confidence: likely.

## Agent Brief

**Category:** bug
**Summary:** Saved DPI (and other volatile device settings) must be re-applied whenever the mouse comes back online, including after a mouse power cycle or the mouse's own sleep, with the PC staying awake.

**Current behavior:**
After the mouse sleeps or is power-cycled it returns to default DPI and Mouser does not re-send the saved value; the user must nudge the slider.

**Desired behavior:**
On every transition of the device from unreachable to reachable (first HID++ response after sleep, receiver link-up notification, re-enumeration), the agent re-applies diverts and replays saved DPI, SmartShift/scroll mode and wheel settings. A missing divert acknowledgement triggers a session reconnect. Detection must not rely on periodic polling while idle.

**Key interfaces:**
- HID session event `device_link_up` (distinct from process start and from OS resume).
- Settings replay entry point shared with #263 and #255.

**Acceptance criteria:**
- [ ] Unit test: fake device reports link-down then link-up on the same open handle; a DPI write with the saved value is issued exactly once per link-up.
- [ ] Unit test: link-up with an unacknowledged divert causes a reconnect, not a silent success.
- [ ] Manual, MX Master 2S over Unifying: set 1600 DPI, flip the mouse power switch off then on, wait 10 s; DPI reads 1600 without touching the GUI.

**Out of scope:**
- OS suspend/resume handling (#263)
- Changing the DPI range or presets
