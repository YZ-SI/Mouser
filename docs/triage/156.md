# #156 [Bug] Device mappings are reported incorrectly, and changing them doesn't work.

> *This was generated by AI during triage.*

## Root cause (Mouser evidence)

- The report is an M720 Triathlon behind a receiver. Device info shows `product_id 0xC52B` (a receiver PID shared by several M-series devices) and `ui_layout: mx_master_3s`, so 3.6.0 showed an MX Master 3S button set (horizontal wheel, gesture swipes).
- The physical gesture button is CID `0x00D0` (flags `0x0171` in the reporter's `reprog_controls`). The reporter's `gesture_candidates` is `["0x00D7"]`, the firmware's virtual control, not the physical button, so remaps never fired. Default candidates are `(0x00C3, 0x00D7)` (`core/logi_devices.py:18`).
- The reference tree already fixes this: `M720_BUTTONS` (`core/logi_device_catalog.py:116`) and the `m720_triathlon` entry (`core/logi_device_catalog.py:393-408`) with `gesture_cids: (0x00D0, 0x00D7)`. Shared receiver PIDs are deliberately not listed in `product_ids`; the model is matched by name/alias (`core/logi_device_catalog.py:348-355`).
- UI buttons are also filtered by live capabilities (`core/logi_devices.py:310-320`). Candidate selection: `_choose_gesture_candidates` (`core/hid_gesture.py:1662`), divert loop `_divert` (`core/hid_gesture.py:1695`).

Confidence: likely. CID facts come from the reporter's JSON; the 3.6.0 code path is inferred from that JSON (no log provided).

## Agent Brief

**Category:** bug
**Summary:** Identify the device correctly behind a shared receiver PID, offer only buttons it really has, and divert the correct physical control.

**Current behavior:**
A device behind receiver PID `0xC52B` is shown with a wrong layout (horizontal wheel, gesture swipes). Remapping the physical thumb/gesture button does nothing because the wrong CID is diverted.

**Desired behavior:**
- A receiver-level PID alone never selects a specific model. The model comes from the paired device name and is matched against the catalog by name or alias.
- For an M720 Triathlon the buttons are middle, back, forward, horizontal tilt, and a gesture button using CID `0x00D0`, tried before `0x00D7`.
- For an unknown model, the offered buttons derive from the live `REPROG_CONTROLS_V4` list: only divertable controls are offered.

**Key interfaces:**
- Device catalog entry (`gesture_cids: Vec<u16>`, `supported_buttons`, `product_ids`, `aliases`); `product_ids` empty for shared receiver PIDs.
- `capabilities_from_controls(controls, device_spec) -> Capabilities`, a pure function of the REPROG control list.
- Gesture divert routine: tries `gesture_cids` in order and reports which CID succeeded.

**Acceptance criteria:**

- [ ] Unit test: the same list with an unknown name yields only buttons derived from divertable controls.
