## Root cause (Mouser evidence)

Confidence: **guess**.

- Report: with Lenovo Legion Toolkit (LLT) focused, a gesture button press does nothing; after clicking the desktop it works. Connection: Bluetooth. The mapped action is not stated; no log.
- Most likely cause: Windows UIPI. Mouser runs non-elevated (`Mouser.spec:243`, `uac_admin=False`) and synthesizes actions with `SendInput` (`core/key_simulator.py:271-273,353,398,415`). Input injected by a non-elevated process is dropped when the foreground window belongs to an elevated process. LLT is commonly run elevated. After clicking the desktop (explorer, non-elevated) injection works again. The HID gesture event itself is not affected (it comes from HID, not a window). I found no elevation/integrity check or `SendInput` return-count handling in `core/key_simulator.py`, `core/mouse_hook_windows.py` or `main_qml.py` (grep for `IsUserAnAdmin`, `uiAccess`, `elevat` found nothing relevant), so the failure would be silent.
- Alternatives (unchecked): LLT consumes the first click for focus; the mapped action depends on foreground app detection failing for an elevated process (`core/app_detector.py` not inspected for this).
