# #209 [Bug] Two bugs: auto screen lock failure & language settings not saved

> *This was generated by AI during triage.*

**State:** `ready-for-agent` (two sub-bugs; the screen-lock one is a likely cause only)

## Root cause (Mouser evidence)

Sub-bug 1, screen auto-lock blocked:
- No `SetThreadExecutionState` or similar inhibit call exists in `core/`, `ui/` or `main_qml.py` (a grep for those names found nothing), so Mouser does not explicitly block the lock.
- Likely cause: periodic HID++ traffic that keeps the wireless mouse awake or looks like activity. `core/engine.py:1368-1420` `_battery_poll_loop` wakes every 5 s and reads battery/SmartShift; throttling lives in `_background_hid_poll_allowed` (`core/engine.py:1340-1362`, `BACKGROUND_HID_POLL_IDLE_GRACE_S = 60` at `:38`) and `_system_idle_seconds` (`:42-64`). The issue thread says the idle-timer part was addressed by upstream PR #225. Not verified on hardware.

Sub-bug 2, language not saved:
- `main_qml.py:1394-1402` `_save_language` loads the config from disk, sets `settings.language`, saves.
- `ui/backend.py` keeps its own in-memory `self._cfg` from startup and writes it whole with `save_config(self._cfg)` (e.g. `:603,662,676,712,1251,1508`). Any later backend save overwrites `language` with the stale value, so the choice is lost on restart. The upstream PR #304 comment describes the same stale-config overwrite.

Confidence: likely for sub-bug 2; guess for sub-bug 1.

## Agent Brief

**Category:** bug
**Summary:** (a) The resident agent must not prevent Windows from auto-locking or sleeping; (b) the chosen UI language must persist across restarts.

**Current behavior:**
(a) With Mouser running the system never auto-locks; it works after quitting Mouser. (b) After choosing a non-English language and restarting, the UI is English again.

**Desired behavior:**
(a) With the GUI closed and the mouse idle, the agent produces no input events, fires no timer more often than once per 60 s while idle, makes no execution-state requests, and sends no HID++ traffic that wakes the mouse; the OS idle timer is unaffected. Battery and similar reads happen on demand (from the GUI) or on device-reported events only.
(b) Config writes are read-modify-write of only the keys the writer owns (or serialized through one owner), so a GUI language change is never reverted by a write of other keys by either process. Language stays in the existing `settings.language` key.

**Key interfaces:**
- `config.json` `settings.language`: unchanged shape.
- Config store API: `update(path, value)` with merge-on-write and atomic replace, used by both processes.
- Agent idle behavior: no polling timers while no GUI is connected on the pipe.

**Acceptance criteria:**
- [ ] Unit test: write `settings.language = "zh-CN"`, then another writer updates `settings.dpi` from a stale snapshot; the reloaded config still has `zh-CN`.
- [ ] Unit test: two concurrent writers to different keys never lose either update (100 iterations).
- [ ] Manual: set the Windows lock timeout to 1 minute, close the GUI, leave the mouse untouched; the PC locks on time with the agent running.
- [ ] Agent idle test: over 10 minutes with the GUI closed, a fake HID backend counts zero requests and no execution-state API is called.

**Out of scope:**
- New languages or a "System default" language option (upstream PR #304)
- macOS start-at-login
