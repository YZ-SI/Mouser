# #116 [Bug] Default profile does not work when certain programs are in foreground

> *This was generated by AI during triage.*

**State:** ready-for-agent

## Root cause (Mouser evidence)

- Reporter: gesture button (Task View) and horizontal scroll (volume) in the default profile do nothing when Task Manager, Honkai: Star Rail, or Zenless Zone Zero is foreground.
- Task Manager runs elevated. Mouser runs non-elevated (`Mouser.spec:243`, `uac_admin=False`). Windows UIPI discards `SendInput` from a lower-integrity process when the foreground window belongs to a higher-integrity one. All actions are synthesized with `SendInput` (`core/key_simulator.py:389`, `send_key_combo`; media keys and scroll injection follow the same route, e.g. `inject_scroll` at `core/key_simulator.py:347`), and the hook swallows the physical event when a binding exists (`core/mouse_hook_windows.py:456` onwards, `should_block`). Result: the button press is eaten and the action is dropped.
- Games with anti-cheat often run elevated or filter input, which would give the same symptom. This is not verified; the reporter did not say whether the games run as admin.
- Profile switching is not the cause: `_on_app_change` (`core/engine.py:946`) selects the default profile on no match, and `get_foreground_app_identity` (`core/app_detector.py:293`) returns an empty tuple (keep last profile) if the process path cannot be read, e.g. for protected processes. That can pin a wrong profile, but not drop actions. No code in Mouser detects or handles elevated foreground windows (grep for UIPI/elevation found nothing; not located).

Confidence: likely for Task Manager (UIPI is documented behavior); guess for the two games.

## Agent Brief

**Category:** bug
**Summary:** Remapped actions must work while an elevated window is in the foreground, or the user must be told clearly why they cannot.

**Current behavior:**
With an elevated application focused (Task Manager, some games), remapped buttons are swallowed and the synthesized action never arrives.

**Desired behavior:**
- The agent can run with high integrity without a UAC prompt on each login, by an opt-in setting (`run_elevated` in `settings`, default off) that registers a per-user logon scheduled task with the highest privileges (or removes it when off). The Rust agent is the only component that needs elevation; the Slint GUI process stays non-elevated and talks to it over the named pipe (the pipe's ACL must still allow the non-elevated GUI to connect).
- When not elevated and the foreground process is elevated, the agent does NOT swallow the physical event if it cannot deliver the action: it passes the original click through, and records one state message `foreground_elevated` which the GUI shows as a hint.
- Foreground identity failures (`OpenProcess` denied) keep the last profile, as today, and log the failure once per process.

**Key interfaces:**
- `settings.run_elevated: bool` in `config.json` (additive, defaults false; existing configs load unchanged).
- Pure function `foreground_is_elevated(pid) -> Option<bool>` (token elevation of the foreground process via `GetTokenInformation(TokenElevation)`); `None` when unreadable.
- Event decision: `should_swallow(event, binding, elevated_self, fg_elevated) -> bool`, unit-testable.
- IPC message `{"type":"state","foreground_elevated":bool}`.

**Acceptance criteria:**
- [ ] Unit test: `should_swallow` is false when self is not elevated, the foreground is elevated, and the action is synthesized; true otherwise.
- [ ] Unit test: loading a v11 `config.json` without `run_elevated` yields `false` and writes no unknown-key churn.
- [ ] Manual (MX Master 2S over Unifying), `run_elevated` off: with Task Manager foreground, the bound button click is not swallowed (native behavior) and the GUI shows the elevation hint.
- [ ] Manual, `run_elevated` on after next login: with Task Manager foreground, horizontal scroll adjusts volume and the gesture button opens Task View.
- [ ] Toggling `run_elevated` off removes the scheduled task.
- [ ] Manual with one of the reported games: record whether it works elevated; if anti-cheat blocks injected input, document it (game behavior, not a bug).

**Out of scope:**
- Bypassing anti-cheat.
- Elevating the GUI process.
- Installer/service design beyond the scheduled task.
