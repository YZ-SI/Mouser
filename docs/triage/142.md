# #142 [Bug] Gesture Button Not Working MX Anywhere 3

> *This was generated by AI during triage.*

**State:** ready-for-agent

## Root cause (Mouser evidence)

- The MX Anywhere 3 has no physical gesture button. Its `reprog_controls` (reporter JSON) list CID `0x00D7` ("Virtual Gesture Button", `core/hid_gesture.py:934`) with flags `0x03A0` and `mapping_flags 0x0000`, and CID `0x00C4` (flags `0x0531`), the wheel-mode (SmartShift) button below the wheel.
- The reporter says pressing the button "changes the feel of the scroll wheel". That is the SmartShift ratchet toggle, i.e. `0x00C4`/`mode_shift`, which the firmware handles itself unless diverted. In 3.6.0 the GUI offered a "Middle (Gesture)" hotspot (bound to the virtual `0x00D7`), so the real button was never diverted.
- The reference fixes the layout: the `mx_anywhere_3` catalog entry uses `MX_ANYWHERE_SMARTSHIFT_BUTTONS` including `mode_shift` (`core/logi_device_catalog.py:270-281`, tuple at `:68-71`), and its layout has a "Mode shift button" hotspot (`core/logi_device_catalog.py:1070+`, hotspot after xbutton2/hscroll). Mode-shift down/up are handled by `_on_hid_mode_shift_down` (`core/mouse_hook_base.py:591`). `mode_shift` availability is gated on `0x00C4` being divertable (`core/logi_devices.py:751, 775-777`).
- A commenter with an MX Anywhere 2 (`ui_layout: generic_mouse`, only middle/xbutton1/xbutton2 offered, gesture CID 0x00D7 only) reports the same symptom; the MX Anywhere 2 wheel button likewise has no gesture button. Not located: a verified mapping for that device.

Confidence: likely.

## Agent Brief

**Category:** bug
**Summary:** For devices without a physical gesture button, the GUI must not present the firmware's virtual gesture control as a button; the wheel-mode button must be remappable instead.

**Current behavior:**
On an MX Anywhere 3 (and similar), the GUI shows a "gesture" button mapped to the virtual CID `0x00D7`. Binding it does nothing. The real wheel-mode button still switches the ratchet and cannot be remapped.

**Desired behavior:**
- A button named "Gesture" is offered only when the device has a physical gesture control according to its catalog entry or a rawXY-capable divertable control that is not the firmware's virtual one.
- When `REPROG_CONTROLS_V4` reports CID `0x00C4` as divertable, the wheel-mode button is offered as "Mode shift button". Diverting it suppresses the hardware ratchet toggle; when the binding is cleared the divert is released and the default behavior is restored.
- Unmapped buttons keep their firmware behavior.

**Key interfaces:**
- Device catalog entry for MX Anywhere 3: supported buttons include `mode_shift`, exclude `gesture*`.
- `capabilities_from_controls()` (pure function): `mode_shift` true iff CID `0x00C4` is divertable; `gesture` true only if a non-virtual gesture CID is divertable.
- HID++ divert/undivert request for CID `0x00C4`.

**Acceptance criteria:**
- [ ] Unit test: the reporter's MX Anywhere 3 control list yields `mode_shift = true` and no gesture buttons.
- [ ] Unit test: the MX Anywhere 2 list from the thread yields only buttons it actually has.
- [ ] Manual (device with SmartShift button, such as MX Master 2S over Unifying, as proxy since MX Anywhere 3 is not available): binding `mode_shift` to an action fires it on press and the ratchet does not toggle; clearing the binding restores the toggle.
- [ ] Clearing all bindings on exit/agent stop undoes every divert (verify via `getCidReporting` readback).

**Out of scope:**
- MX Anywhere 2 hardware specifics beyond not offering nonexistent buttons.
- Gesture swipes (the device lacks them).
