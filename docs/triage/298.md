# #298 [Bug] After resuming PC from sleep, Smartshift is automatically turned on + horizontal scroll inversion is automatically disabled

> *This was generated by AI during triage.*

**State:** ready-for-agent (same trigger as #342, covers Smart Shift and thumb-wheel native invert; implement together with #342)

## Root cause (Mouser evidence)

Confidence: **likely**.

- Smart Shift mode and the firmware-side wheel/thumb-wheel invert are device-volatile. They are restored only by `_run_saved_settings_replay` (Smart Shift: `core/engine.py:1161-1257`) and, for native invert, only from the connection-change branch (`core/engine.py:1310-1318` -> `_apply_wheel_invert_setting`, `core/engine.py:665-705`); the HID layer also re-queues the last invert target on reconnect (`core/hid_gesture.py:3262-3272`). All of these require the listener to notice a disconnect/reconnect (3 timeouts, `core/hid_gesture.py:3362-3410`), which does not happen when the UI is closed (`core/engine.py:1340-1341` gates polling on `_frontend_visible`), and no Windows resume/unlock hook exists (`core/mouse_hook_windows.py:536-538`).
- The UI shows "Invert horizontal scroll: on" because it reflects config, but the firmware flag was reset: matches "option still on but works like off".
- `_run_saved_settings_replay` itself does not re-apply native wheel invert (confirmed by reading `core/engine.py:1161-1257`); it relies on the reconnect branch. A resume-only trigger that skips the connection branch would still leave invert off.
- Two other users commented (Sonoma, Win11) "resets after wake, need to restart Mouser". Not verified.

## Agent Brief

**Category:** bug
**Summary:** After sleep/resume or unlock, Smart Shift mode/threshold/force and horizontal+vertical wheel invert must be restored to the saved config on the device.

**Current behavior:**
After PC resume, the device reports Smart Shift enabled and the thumb-wheel invert behaves as non-inverted, although config says Smart Shift off and `invert_hscroll` on.

**Desired behavior:**
The same replay trigger set defined in #342 also restores: Smart Shift (mode, enabled, threshold, scroll force), native vertical and horizontal wheel invert state, and wheel divert flags. When the native invert write is unavailable or fails, the agent falls back to software inversion in the mouse hook so behavior matches the saved config (never both applied, which would double-invert).

**Key interfaces:**
- The shared `replay_saved_settings(reason)` from #342 must include native wheel invert and Smart Shift, ordered: Smart Shift first, then wheel invert, then DPI.
- The `native_invert_active` flag used by the hook to decide software inversion must be recomputed after each replay.

**Acceptance criteria:**
- [ ] Unit test with mock device: after a `ResumeAutomatic` event, writes include Smart Shift set to the saved mode/threshold/force and wheel invert set for saved `invert_hscroll`/`invert_vscroll`.
- [ ] Unit test: if the native invert write fails, software inversion is active and `native_invert_active == false`; if it succeeds, software inversion is off (no double inversion).
- [ ] Manual (MX Master 2S over Unifying if it exposes these features; otherwise MX Master 3S): Smart Shift off, invert hscroll on, sleep/resume the PC: ratchet/free-spin matches config and thumb wheel direction is inverted, no GUI opened.

**Out of scope:**
- Redesign of the Smart Shift UI.
- Devices without Smart Shift / thumb wheel.
