# #263 Mouser has no effect after resume (dons't work at all)!

> *This was generated by AI during triage.*

**State:** `ready-for-agent`

## Root cause (Mouser evidence)

- `core/mouse_hook_windows.py:536-538` handles only `WM_DEVICECHANGE` with `DBT_DEVNODES_CHANGED`; `:700-722` `_on_device_change` / `_reinstall_hook` only re-install the low-level mouse hook. A grep for `WM_POWERBROADCAST`, `PBT_` and resume in `core/` found nothing, so there is no resume or unlock handling at all.
- `core/hid_gesture.py:2093-2100` `force_reconnect()` exists but nothing calls it on resume. The HID loop only recovers on a read error or after 3 consecutive request timeouts (`core/hid_gesture.py:3361-3380`); a stale handle after sleep may read nothing without raising.
- `core/engine.py:1340-1345` `_background_hid_poll_allowed` returns False when the window is hidden, so the polling that would expose the dead handle is off in tray mode. A maintainer comment on the issue says the same.
- Reconnect replays settings via `core/engine.py:1161-1257` `_run_saved_settings_replay`, which only runs when `hid_features_ready` flips (`core/engine.py:1338`).

Confidence: confirmed that no resume handling exists; likely that stale HID handle plus disabled polling is the whole failure (matches the maintainer comments).

## Agent Brief

**Category:** bug
**Summary:** After system sleep/resume (and session unlock), the agent must restore the mouse hook, HID++ session, diverts and saved settings without a restart.

**Current behavior:**
After resume from sleep, remapping and HID features stop working until the app is restarted. The hook is only refreshed on device-node changes; the HID handle is never dropped on resume.

**Desired behavior:**
The agent listens for power and session events (resume from suspend/standby, session unlock, display on). On each event it re-installs the low-level mouse hook, closes and re-opens the HID++ handle, re-applies button diverts, and replays saved DPI and SmartShift/scroll settings. If the device is not yet reachable it retries with bounded backoff (cap 30 s) until it appears. Overlapping events coalesce into one recovery run. Recovery must not need the GUI and must not add periodic polling while idle.

**Key interfaces:**
- Agent power/session event source (hidden message window handling `WM_POWERBROADCAST`, `WM_WTSSESSION_CHANGE`).
- HID session `reconnect()`: safe from any thread and idempotent.
- Settings replay entry point shared with link-up handling (see #249).

**Acceptance criteria:**
- [ ] Unit test: a synthetic resume event triggers exactly one hook reinstall, one HID reopen and one settings replay, even when three events arrive within 2 s.
- [ ] Unit test: with a fake HID backend that fails the first N opens, recovery retries with backoff capped at 30 s and succeeds once the backend recovers.
- [ ] Manual, MX Master 2S over Unifying: set a non-default DPI and a remapped button; sleep and wake the PC; within 10 s of wake the remap works and DPI matches the saved value, GUI never opened.
- [ ] No timer or thread persists after recovery beyond the steady-state set (no growth across 50 simulated resume cycles).

**Out of scope:**
- Mouse-only power cycle with no OS sleep (see #249)
- macOS soft-sleep behavior
