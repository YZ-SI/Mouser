# #270 [Bug] Mouser on Windows won't open unless launched as Administrator

> *This was generated by AI during triage.*

**State:** `ready-for-agent` (bug in Mouser; the rewrite must satisfy the contract by construction)

## Root cause (Mouser evidence)

- `core/update_installer.py:544-566` `_probe_directory_writable` creates a temp file via `tempfile.mkstemp(dir=...)` and returns False on `OSError`.
- `core/update_installer.py:591-596` `locate_runtime` calls that probe on `root.parent` (the folder ABOVE the install folder, e.g. `C:\` or `C:\Program Files`), not on the install dir. A non-elevated user cannot write there.
- `ui/backend.py:438-439` calls `_consumeUpdateResultMarker()` and `_cleanupStaleUpdatePreparation()` during backend init; both call `locate_runtime()` (`ui/backend.py:1331,1342,1374`). `ui/backend.py:909-911` `updateInstallEnabled` also reaches the updater code.
- Reporter confirmed: moving the install from `C:\Mouser` to `C:\Mouser_Install\Mouser` fixed it; a second reporter has it under `C:\Program Files\Mouser`. A third sees the process hang at about 6% CPU with no tray.

Why it hangs rather than just disabling updates: not located. By the code I read, the probe returns False on access denied, so startup should continue. The loop shown in the reporter's screenshot is in the update/startup path, but I could not find it in the files I opened.

Confidence: likely that the parent-dir write probe / updater path triggers it (the reporter's workaround matches); guess for the exact hang mechanism.

## Agent Brief

**Category:** bug
**Summary:** The agent and GUI must start fully (tray, hook, HID, UI) as a standard non-elevated user from any install directory, including a read-only one such as `C:\Program Files\Mouser`.

**Current behavior:**
In Mouser the startup path probes write access to a directory outside its own data folders. When the install is under a protected location and the user is not elevated, the process hangs (no tray, no window, no remapping).

**Desired behavior:**
Neither process writes anywhere except the per-user data dirs (`%APPDATA%\Mouser`, `%LOCALAPPDATA%\Mouser`) and the named pipe. No startup step depends on the install directory or its parent being writable. A failure of any optional step (update check, write probe, autostart registration) is logged and skipped, never blocks startup, and never busy-loops. An in-place self-updater is not part of this contract.

**Key interfaces:**
- Agent entry point: tray and hooks come up before any optional I/O.
- GUI entry point: opens the window without touching the install dir.
- Config/log path resolution: only per-user dirs.

**Acceptance criteria:**
- [ ] Integration test: install the built agent and GUI into a directory with a deny-write ACL for the test user (stand-in for `C:\Program Files`); both start, the tray icon appears, and the hook is installed within 2 s.
- [ ] Same test: agent CPU averages under 1% over 30 s idle after start (no spin loop).
- [ ] A test or static check asserts no code path creates files outside the per-user dirs.
- [ ] Manual, MX Master 2S over Unifying, standard user, installed in `C:\Program Files\Mouser`: button remaps work.

**Out of scope:**
- Auto-update / self-replace of binaries
- Running elevated to reach elevated windows (documented limitation)
