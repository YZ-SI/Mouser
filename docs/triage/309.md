# #309 [Bug] Windows 11, MS Project - Shift + Vertical Scroll

> *This was generated by AI during triage.*

**State:** ready-for-agent (contract picks a simple opt-out; default keeps current behavior)

## Root cause (Mouser evidence)

Confidence: **confirmed**.

- The Windows low-level hook unconditionally converts any vertical wheel event with Shift held into a horizontal wheel event: `core/mouse_hook_windows.py:424-440` (`GetAsyncKeyState(VK_SHIFT) & 0x8000` -> `_pending_shift_hscroll` -> `WM_APP_INJECT_SHIFT_HSCROLL`), injected at `core/mouse_hook_windows.py:528-534` via `_inject_scroll_impl(MOUSEEVENTF_HWHEEL, delta)`. The original event is swallowed (`return 1`).
- Microsoft Project binds Shift+wheel to its own action (expand/collapse summary task) which needs the native `WM_MOUSEWHEEL` with Shift down. The translation removes it. Windows already handles Shift+wheel as horizontal in most apps; the translation targets apps that do not.
- No config option, per-app exclusion, or profile gate exists for this translation: the branch checks only Shift state and `_ri_hwnd`. I did not find a toggle in the hook; a config key for it is not located.

## Agent Brief

**Category:** bug
**Summary:** Make the Shift+vertical-wheel -> horizontal-scroll translation optional and per-profile/per-app, with pass-through when disabled.

**Current behavior:**
While Shift is held, every wheel notch is swallowed and replaced with a horizontal wheel event in all applications, including ones (Microsoft Project) that give Shift+wheel their own meaning.

**Desired behavior:**
A boolean setting `shift_wheel_hscroll` (default `true`, preserving current Mouser behavior) controls the translation. It is resolvable per profile, so a profile bound to `WINPROJ.EXE` can set it `false`; when false the original wheel event is passed through untouched (no swallow, no injection). Persisted in `config.json` as an additive key; older configs load with the default.

**Key interfaces:**
- `config.json` settings key `shift_wheel_hscroll: bool` (global default) and optional per-profile override of the same key.
- Pure hook decision function `should_translate_shift_wheel(profile, shift_down) -> bool`, unit-testable.
- GUI toggle on the scroll settings page (agent exposes it over the pipe as part of the settings snapshot).

**Acceptance criteria:**
- [ ] Unit test: `should_translate_shift_wheel` returns false when the active profile sets `shift_wheel_hscroll=false`, true by default.
- [ ] Unit test: an older config without the key loads and defaults to true.
- [ ] Manual: with a profile for `WINPROJ.EXE` set to false, Shift+wheel in MS Project expands/collapses a summary task as it does without Mouser; with default settings behavior in other apps is unchanged.
- [ ] When disabled, the hook emits no injected scroll events (verified with a test tool that watches `LLMHF_INJECTED`).

**Out of scope:**
- Reproducing MS Project in CI.
- Any other scroll translation (invert, smooth scroll).
